# Workflows and Closure Conditions

这些是能力语义，不是强制流水线。Agent 应根据任务规模合并、跳过或重排步骤，但必须满足对应完成条件。

## Orient

目标：用有限上下文建立对 Vault 的可靠心智模型。

完成条件：

- 已确认 Vault 边界、主题、语言和自动写入策略；
- 已找到主要 Map、Index、近期变更和未决问题；
- 能说明接下来为什么读取某些页面，而不是盲目全库扫描；
- 未把 Binding 或 Runtime 内容误当作知识。

## Ingest

输入可以是 `sources/inbox/` 文件、已注册 Source Record、用户指定的本地文件或用户授权获取的外部材料。代码仓库必须先按 [repository-ingest.md](repository-ingest.md) 注册为“名称 + 链接 + 根 README”合成 Source，不得将仓库副本或源码写入 Vault。

完成条件：

- Source 已保存或注册，路径和身份可追溯；
- 核心主张、限制、时间范围与重要证据已被识别；
- 相关已有页面得到增量更新，必要时才新建页面；
- 新旧资料的支持、补充或冲突关系被显式表达；
- 新知识可由 Index/Map 发现；
- Source Record 的状态和受影响页面已更新；
- 操作日志记录了范围、证据和未决问题。

反例：只写一篇 Source Summary，未检查已有概念、实体或分析页。

## Query / Explore

检索顺序默认是：Wiki 综合页 → 相关 Source Record / Evidence → 原始 Source。外部搜索只有在 Vault 不足且用户允许时才使用。

完成条件：

- 回答区分“来源明确的事实”“跨来源综合”“Agent 推断”“当前未知”；
- 引用指向可复查页面或 Source；
- 对冲突信息给出并列解释，不伪造一致性；
- 若结果有长期价值，已判断是否需要 Promote；
- 临时回答不会被自动当作持久知识。

## Promote

适合持久化的结果通常同时具备：可复用、相对稳定、对现有结构有增量价值、证据充足。纯格式化结果、一次性操作、未经验证猜测通常不应持久化。

完成条件：

- 选择了最合适的已有页或新页面类型；
- 结论、证据、不确定性和适用范围完整；
- 与相关页面建立双向可发现关系；
- Index/Map 和日志已更新；
- 若改变核心结论，已按 Change Policy 取得用户决定。

## Reconcile / Maintain

关注：矛盾、陈旧结论、复制状态、重复页面、孤立页面、缺失来源、断链、过大页面、过碎页面、已失效问题、值得引入的新来源。

完成条件：

- 发现项带具体页面与证据，而不是泛泛建议；
- 可安全自动修复的链接、元数据和索引问题已经修复；
- 涉及语义裁决的冲突保留各方依据并升级给用户；
- 维护结果和残留风险写入日志；
- 没有把 Lint 变成强制统一所有页面格式的借口。
