# Flexible Page Model

## 设计目标

页面模型提供共享语言，而不是刚性本体。Vault 可以按领域增加、合并或停用类型。

建议类型：

- `source`：某个注册来源的身份、摘要、限制、影响页面；
- `concept`：术语、方法、机制、模式；
- `entity`：人物、组织、产品、项目、模型、设备；
- `analysis`：比较、综合、论证、趋势、方案；
- `question`：待验证问题、研究缺口、下一步；
- `decision`：用户或团队作出的知识结构/结论裁决；
- `map`：领域导航与关系说明。

## 最小 Frontmatter

新建知识页面时建议包含：

```yaml
---
title: 页面标题
type: concept
status: active
created: 2026-08-31T00:00:00Z
updated: 2026-08-31T00:00:00Z
---
```

只有在确有信息时再增加 `sources`、`aliases`、`tags`、`confidence`、`supersedes` 等字段。不要为了填满模板编造值。

## 页面粒度

考虑拆页的信号：

- 一个概念被多个主题反复引用；
- 页面包含相互独立、演进速度不同的主结论；
- 修改一部分内容经常导致整页难以审查；
- 某实体或问题已形成独立证据链。

考虑合并的信号：

- 两页长期重复相同事实和来源；
- 子页面没有独立入链、独立结论或维护价值；
- 过度拆分使一次理解需要无意义地打开大量页面。

## 链接

标准 Markdown 链接与 Obsidian Wikilink 均可。默认优先使用相对 Markdown 链接，因为它同时被 GitHub、普通编辑器和 Obsidian 支持。一个链接应表达真实关系，避免仅为“增加链接数”而连接。
